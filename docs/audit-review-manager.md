```powershell
.\.venv\Scripts\python.exe -m astralogue audit webui
```

打开 <http://127.0.0.1:8340>，刷新此前打开的页面。

- 列表展示章节、任务、小节、片段名称和实际台词预览。
- 排列优先使用已记录 Reader 路径中的位置，尚未进入已记录路径的片段使用来源小节位置。未确定的归属明确标记，不将编号或提案生成时间作为剧情顺序。
- 详情展示上几条台词、原位置的修改说明、分支正文、下几条台词。同一位置的多个提案是并列建议，不代表额外剧情顺序。
- “具体修改”只包含已绑定实际节点及可检查位置的提案；“研究结论与待定位”中的记录不能批准为播放修改，只能记为已阅、暂缓或驳回。
- 模型原始意见、来源绑定及 JSON 放在技术详情中。审批单独记录，不会直接修改已发布 StoryPack 或存档。
- 位置根据缓存来源和当前 Reader 路径展示，并不等于恢复了游戏的世界状态触发条件。跨小节或未知位置不能当作确定的插入点。

## 批量审核（1.17.0）

列表勾选多项或全选本页，填写审核人后点击通过所选/驳回所选。每批最多 40 项；包含未具备具体修改位置的提案时，通过操作整批拒绝，不会偷偷略过。逐项保存审核日志。研究结论不能批量通过为可执行修改，但可以批量驳回。

## 评论驱动修订（1.18.0）

具体修改：批准、需要修改（必须评论）、驳回。研究内容：批准研究方向（必须评论）、驳回。普通批准/驳回也会保存填写的评论。研究批准仅确认方向，不是可执行 Patch 批准。评论、原始证据与父提案一起进入持久化任务。服务串行处理新评论，不会自动遍历其他未审内容。

选择本地离线模型（默认，127.0.0.1:8339）或 DeepSeek v41f 低推理。DeepSeek 使用现有累计人民币 5 元上限，包含此前费用和保守预留；预算不足停止，不自动切换模型。页面不会加载 GPU 模型，必须事先获得用户许可并启动推理服务。任务失败或超限可查看原因、补充意见重新提交。

模型生成的子提案保持待审核。只有通过现有节点/位置检验的子提案进入具体修改；未形成具体提案时显示原因，不能为了转入具体修改而编造节点。原始建议、评论、模型调用及子提案分别保留。

提交成功后按钮禁用显示已批准、已驳回或等待修改。右侧说明栏桌面端 sticky；窄屏正常流排版。详情可增加前后文数量，最多前后各 100 条，沿当前已记录阅读路径，不推断分支顺序。模型修订进度可刷新查看。

实测：独立测试数据库中，本地 9B 完成一次真实评论判别，协议验证通过，但未生成具体修订提案；页面应保留需要补充证据状态，不能宣称模型已恢复剧情。生产数据未因此获得自动审批。

## 自动增量发布与返修（1.19.0）

只有最终点击“批准”的具体提案才进入发布。研究方向批准、需要修改和模型生成的新申请都不发布。发布前检查原始哈希、节点、重叠与新增验证错误；不支持或冲突操作保留批准记录并醒目显示发布失败。已发布内容若需撤销，先回滚对应最新修订，避免审核状态与实际包不一致。

当前发布目标来自 data/launcher.json，仍是原来的 .storypack 路径。用户选择其他独立包不会自动更新。本机使用同一包的 Reader 后续控制推进可读取新关系；已经处于旧分支内部的会话不会被强制跳走。载体、昵称和已做选择不清空。

pack_id / pack_version 作为基础包身份保持不变，live_revision 单独记录兼容更新，required_capabilities 增加 live-reader-revisions-v1，以便旧引擎明确拒绝不支持的包。每次修订仅记录改变行及元数据字段的压缩前后差异，和数据变更一起事务提交；历史就在 StoryPack 内，无运行时上游依赖。普通包仍使用 Schema 1。

```powershell
.\.venv\Scripts\python.exe -m astralogue audit publish
.\.venv\Scripts\python.exe -m astralogue audit history
.\.venv\Scripts\python.exe -m astralogue audit rollback
```

rollback 仅撤销最新活动修订，不复制整包；在新增节点上的存档可能需要回到兼容位置，操作前应让读者退出。SQLite WAL 是事务日志，正常发布会 checkpoint；复制数据包前应关闭进程并完成 checkpoint，不能只复制尚未落盘的主文件。

实测发布6项已批准内容，保留原数据包基础身份；真实 CLI 主线137句、探索159句，二者差异可由已审核可选互动解释。旧基线主线158句，现有21个对话实例不再自动混入主线。历史共615,103字节，未生成新 .storypack 文件。

评论返修协议不再接受空 proposals 或原样旧申请。新申请列于“模型返修申请”，仍等待人批准；无法恢复的内容必须明确报告缺口。后台重启会恢复遗留运行任务；详情每5秒检查新申请并给出链接，不刷新未提交的评论输入。

评论返修允许一次生成1–3份独立申请，解析器和模型约束同时检查上限，人工逐份批准；零份、超过三份或原样复制旧申请都不作为完成。后续拆分成功时，只将前一轮尚未审批的申请标为被替代，保留全部历史，不撤销已有人工决定。

## 选项与申请说明（1.21.0）

分支详情将当前游玩包的相关菜单、玩家可见的建议选项文字与分支回应分别展示。Reader 主动互动的选项文字取自 after.interaction（缺失时明确展示发布器默认“额外互动”），不能将回复正文当作选项。不改变选项的必经标记也明确说明。

模型可在 explanation 写面向人工审核的中文申请说明，描述改哪里、为什么及未确定内容；这不是剧情原文。已有中文 rationale 可直接展示，历史英文意见仍保留在技术详情。

模型可在 additions 提出有来源的补句，每句包含 speaker、text、evidence。只接受所引真实来源能找到的原文，不允许把 human_direction 等评论当作官方文本。补句独立展示，保留来源，不改写 TextMap。目前新增节点及插入位置尚未接入发布器，因此含 additions 的提案不能作为可直接发布的具体修改，也不会批准后静默丢掉补句。

验证：完整回归290项通过；相关定向22项通过。真实游玩包的菜单选项对照在HTTP详情中可见；补句来源校验拒绝伪造文本及评论冒充原文。

## 撤销和关联复核（1.22.0）

已驳回详情可“撤销驳回，恢复待审核”。已批准研究方向可“撤销研究批准及其后续申请”：原研究回到待审核，其多轮返修的后续申请标为已随研究撤回，全部相关任务取消，迟到输出不再生成申请。撤回申请不能从旧页面重新批准，需从原研究重新发起。评论和审核记录不删除。

已发布的后续申请只有属于该研究的最新连续后缀才可事务回滚；存在其他研究的后续发布会拒绝整个撤销，保留原状态。撤销不能退回已经发生的API费用，已发送推理请求可能继续完成，但结果不再被接纳，用量仍记录。

每次模型草案产生后检查当前已有申请，包含已批准和已发布内容。相同节点、同版本来源块、同任务同小节或相同长句构成关联候选；关联不自动视为冲突，也不会合并复用文本的不同触发实例。发现关联时先暂存草案，把相关申请、状态、节点和来源发给同一模型额外复核一次，再形成最终待审申请。详情显示关联申请链接和送审时状态。额外阶段同样受本地上下文及DeepSeek累计5元上限约束，不自动切换模型，失败会显示原因。

模型审核说明要求中文；新调用拒绝纯英文 explanation、rationale、uncertainty、unknowns 和 conflicts，机器字段与来源原文保持原样。历史原始输出不改写。

## 提交时间与旧研究清理

新增申请在插入时自动记录UTC提交时间，新增任务另记排队时间；列表与侧栏统一显示北京时间（UTC+8）。审批和返修不会改写首次提交时间。数据库以兼容列及触发器升级，旧记录没有精确时间仍为NULL并显示“未记录（旧申请）”。

按用户授权的2026-11-04 21:20（含）截止，从默认审核列表删除了66条旧研究/待定位。缺乏精确时间的历史记录通过先前固定快照和已展示记录的提交上界判断，依据保存于 legacy_submission_upper_bounds；不按ID排序或审批时间猜测创建时间。无法确认时间的记录不会自动删除。删除操作保留原状态、原文与审计日志，历史详情只读，不等同于撤销研究授权，因此截止后发起的新申请和已发布剧情不因清理列表被撤销。

新模型调用面向人工的说明要求中文。关联复核只追加一轮，与初始调用分别记录用量；已撤销研究的迟到结果不再产生新申请。

验证：全量302项通过、无跳过；定向27项通过，覆盖撤销驳回、递归研究撤回、迟到结果拦截、安全回滚后缀、已批准申请的额外复核、中文说明、旧库无时间迁移和清理时间边界。
