# M5 剩余问题与下一阶段顺序

当前完整命名主线任务验证数为零。后续应以命名任务的端到端完成、真实 Timeline 和世界状态覆盖为目标，
不要以列车访客、片段数、技术记录或已解析文本比例作为替代指标。

1. **取得可核对版本的明文 Timeline 控制资源，或研究非加密容器的正常静态格式。**
   明确区分只含视觉的轨道和台词、事件、选择、状态轨道。
   当前不解密 ENCR，不注入或读取游戏进程，不运行未审查的第三方工具。
   有明确时间/轨道结构时才能生成顺序和并发，不从台词编号或文件名补线。
2. **实现原始 Timeline 的真实适配器并建立实际样本断言。**
   现有 JSON 控制图补充接口只是输入协议；须补上原生资源到该协议的可信解析。
   先选择有完整资源的命名开拓任务，再复核其台词 ID、选项、调用返回和完成条件。
3. **世界状态与任务调度。**
   补充 PropSetupTrigger、物件状态、区域条件、战斗/信息事件和明确的默认状态规则。
   同时就绪的协程需要通用并发调度，不能用排序消除歧义。
   保留异步等待的可保存执行上下文，扩展前先设计旧存档兼容规则。
4. **条件与效果语义。**
   逐类核对 ByCompareMainMissionState、ByHeroGender、SetPerformanceResult、
   FinishActionList 等真实结构及其默认值；未确定时保持阻塞。
5. **扩展资源获取与覆盖率。**
   当前取全量任务定义及代表性控制闭包，尚未取得所有主线控制脚本。
   扩大获取后分别报告资源存在、文本解析、控制链接、可进入、完整执行和全分支证明。
   继续列明九条缺失定义和三个台词引用，直到有可追溯的新版本补全。
6. **跨任务连续播放。**
   依据实际完成条件和声明的后续关系推进；不把 NextTrackMainMission 当作无条件跳转。
   前置条件不可证时回到任务菜单并说明状态缺口，保留已有片段/旧包行为。
